## 4. Safe deployment sequence (each step needs explicit approval)

1. **Admin:** create the Windows VM (4 vCPU / 8 GB / 80 GB+ data disk). Install the VC++ 2015-2022 x64 runtime if `-PreflightOnly` reports it missing. Remove `SanaGtmProbeWeb` from the office PC: `sc.exe delete SanaGtmProbeWeb`, elevated.
2. **Cloudflare:** create a **named** tunnel and a stable hostname (`sanagtm.<your-domain>`). Never use a `trycloudflare.com` name.
3. **Supabase Auth:** add `https://sanagtm.<your-domain>` (and any Pages origin you keep) as Site URL / redirect URLs. This is a production change, so do it at cutover.
4. **VM:** install from `SANA-GTM-Windows-Installer.zip` (verify the `.sha256`). Use the existing `CAREERCLOUD_PLATFORM_SECRETS_KEY` through `PLATFORM_SECRETS_KEY_FILE` or the hidden prompt, never on a command line. Set `EXTRA_CORS_ORIGINS` only if the Pages dashboard stays in use. See `deploy/windows-selfhost/README-WINDOWS.md`.
5. **Rehearsal (test environment):** `sanagtm migrate import <today's or a fresher dump>` on the VM with the **worker off**, then `sanagtm migrate verify <manifest>`. Sign in, check counts and a few records, and check that provider credentials decrypt (the import does this check). Do not point users at it yet.
6. **Cutover window (approval):** stop the office PC worker. Take a final read-only backup (`sanagtm migrate dump-hosted`), then import and verify it. Decide resume or cancel for the paused WAD sweep (section 3). Then `sanagtm start`, and rebuild or point the dashboard at the stable hostname.
7. **Rollback (until the hosted DB is retired):** `sanagtm stop` on the VM, then restart the office PC API and worker. Supabase was only read during the migration, so it is unchanged. Writes made on the VM after cutover are not copied back.

## 6. Known limitations

- **Service mode** (Windows services, start at boot, reboot recovery) has **never been run**. It needs an administrator. User mode passed the end-to-end test without admin rights.
- **Real Supabase sign-in** against a self-hosted install has not been tested. The e2e test uses Supabase-format tokens signed by a test key; the VM verifies tokens with Supabase's JWKS.
- The office PC has only one physical disk, so the backups are not off-machine (section 2).
- The automatic WAD full sweep combined with `stale_after_days 1` caused about 74 MB of history growth in one day (`STORAGE_AND_GROWTH.md`). Self-hosting removes the 500 MB Supabase Free cap, but keep an eye on growth with `sanagtm capacity`.
